# WS-8 R3 Owner helper implementation audit adjudication

Date: 2026-07-16
Audit ID: `99a28021`
Scope: one-command macOS Owner helper, zero-cost behavior lock, existing authorization/proof implementation, and runbook.
Result: all seven panel voices completed. Concrete cleanup, ACL, publication, diagnostic, pending-execution, and contract-test findings were accepted and fixed before commit.

| finding | decision | action | verification |
|---|---|---|---|
| A full pending write followed by `fsync` or close failure could leave a complete pending file. | accepted | Track successful write, fsync, and close as one commit point; unlink the invocation-owned pending path after every earlier exception. | `test_full_write_fsync_failure_removes_pending_file` and focused helper suite. |
| Verification and publication were separated by a root-only content race. | accepted | Reopen with `O_NOFOLLOW`, recheck uid/mode/type/link/size/ACL, and compare exact canonical bytes immediately before publication. | `test_pending_bytes_changed_after_verification_are_not_published`. |
| Hard-link publication could leave both hidden and visible names after an uncatchable crash. | accepted | Use macOS `renamex_np(..., RENAME_EXCL)` for atomic no-clobber publication; retain a non-production portable fallback for cross-platform unit tests. | Success and existing-ready collision tests run on macOS Python 3.9; runbook documents atomic crash states. |
| Hidden pending files remained technically consumable by a root execute command. | accepted | Reject `.capability-pending-*` before loading authority whenever `--execute` is present; non-executing helper verification remains allowed. | `test_execute_rejects_hidden_pending_envelope_before_loading_authority`. |
| POSIX owner/mode checks did not reject macOS extended ACLs. | accepted | Inspect and reject extended ACL entries on authorization roots, proof, pending, and ready envelope; fail closed on ACL inspection errors. | ACL rejection test plus repeated real no-ACL preparation tests. |
| The helper tests mocked the verifier output instead of locking the real `ws8_execute.main` success schema. | accepted | Add a contract integration test through the real verification-default main branch while isolating only document/runtime/source fixture boundaries. | `test_zero_cost_wrapper_matches_real_verifier_success_contract` asserts zero turns and no reservation call. |
| Catchable signal, bootstrap re-entry, and unsafe post-publication metadata paths were under-tested. | accepted | Add explicit signal conversion, pre-prepare re-exec, and ready cleanup tests. | Focused helper suite covers signal, re-exec, metadata failure, verifier failure, and publisher failure. |
| Generic verifier errors made Owner debugging blind. | accepted | Surface one bounded printable local verifier diagnostic while suppressing exact raw proof or protocol content. | Safe-diagnostic and raw-state non-exposure tests. |
| A 20-minute envelope may expire during a slow Owner handoff. | accepted | Keep the conservative short lease and document immediate use plus fresh zero-cost regeneration after expiry. | Runbook section 3 test and expiry payload test. |
| `os.link(..., follow_symlinks=False)` is unsupported before Python 3.12. | rejected | `/usr/bin/python3` 3.9 reports `os.link(src, dst, *, src_dir_fd=None, dst_dir_fd=None, follow_symlinks=True)`; the claim is factually false. Darwin publication now uses `renamex_np` regardless. | Python 3.9 signature probe and focused publication tests. |
| The helper should also generate stress-tier capability envelopes. | rejected | This thin slice is explicitly the first deployment-tier R3 capability gate. Stress capability remains a later distinct authorization workflow; adding it would broaden paid-study scope. | Construction behavior contract and runbook section 3 remain deployment-only. |
| Any successful stderr output should be accepted. | rejected | The attached real verifier success path emits one JSON object on stdout and no stderr. Failing closed on unexpected success diagnostics avoids ambiguous gates; a real-main contract test locks current behavior. | Real verifier contract test passes with empty stderr. |
| Root loads Python from the account-owned canonical checkout. | rejected | This is a valid systemic hardening proposal but not a defect introduced by this helper: the published WS-8 protocol intentionally binds an ordinary-account-owned canonical checkout and the existing paid runner already uses that entry model. Replacing it requires a root-owned runner distribution and cross-phase source-trust redesign, outside this no-paid-helper thin slice. The supported threat is the sandboxed model child, which cannot read or write the checkout; arbitrary pre-existing compromised account processes are excluded by the fresh startup/Owner gate. | Existing proof-bound checkout and model checkout-denial tests remain green; the live Owner zero-cost validation is still mandatory before execution. |
| A live root/launchd fixture is needed to prove the machine-specific boundary. | accepted | Keep this as the explicit post-merge Owner-only zero-cost gate; source tests do not claim live Keychain, Seatbelt, or root state success. | Owner must obtain the three redaction-safe gate values before any `--execute`. |

No accepted source finding authorizes paid execution, reads Owner-only state, or weakens R1/R2 immutability. The broader root-owned runner-distribution proposal remains outside the frozen R3 execution architecture rather than being silently implemented in this helper PR.
